# tmuxde

**Your tmux on any screen. Nothing leaves your network.**

tmuxde (Tmux Development Environment) is a self-hosted web terminal for tmux. It serves the tmux sessions on your machine to any browser on your private network, mainly phones and tablets.

Start a coding agent like Claude Code or Codex, or a long build, at your desk. Then check on it, answer its questions and scroll back through its output from the couch. tmux owns all session state. Closing the browser, locking the phone or rebuilding the containers never kills a session.

## What you get

- Open your existing tmux sessions, windows and panes in any browser. Create and kill them too.
- Mobile keyboard toolbar with Ctrl, Esc, arrows and saved commands.
- Touch scrolling through full tmux history.
- Paste or upload photos. They land on disk as file paths your agent can read.
- Repository browser with files, Git changes and syntax highlighting.
- Installable as a home screen app.
- Optional device lock with PIN or passkey. Stored credentials stay encrypted until you unlock.

## No phone home

tmuxde never talks to anything outside your network.

- No telemetry, analytics or crash reporting.
- No update checks.
- No accounts, cloud services or external APIs.
- No CDN assets. Fonts, syntax highlighting and the editor ship in the bundle.

The setup enforces this as well:

- Web and relay containers run on an internal Docker network with no route to the internet.
- Content Security Policy only allows connections back to your own domain.
- Caddy rejects requests from non-private IP addresses and serves HTTPS from its own local CA.
- Framework telemetry is disabled in development, build and production.

Network access happens only while building: pulling base images and downloading packages. Commands you run inside tmux keep the normal network access of your host.

## How it works

```
Browser ─https/wss─► Caddy ─┬─► web     Next.js client
                            └─► relay   WebSocket bridge ─► host tmux socket
```

The relay attaches to your host tmux server through its socket. It reads files through a read-only bind of your home directory and blocks credential directories. Sign-in uses one relay token generated by setup.

## Quick start

Requires Linux x86_64 with glibc, Docker Compose with volume subpath support, Python 3 and tmux on the host. Start a tmux session first.

```sh
git clone git@github.com:AthennaMind/tmuxde.git
cd tmuxde
scripts/setup.sh
docker compose up -d --build --wait
```

Setup writes a private `.env`, generates the relay token and copies your host tmux client. No Node or pnpm install on the host.

Set `LOCAL_DOMAIN` and `LOCAL_BIND_IP` in `.env` for your network. Defaults are `localhost` and `127.0.0.1`, reachable only from the host. Setup keeps your values on later runs. Trust the Caddy local CA on your devices, following [.docker/README.md](.docker/README.md). Then open your domain and sign in with the token from `.docker/.env.token`.

## Development

All Node tooling runs in Docker. Source edits hot reload.

```sh
docker compose run --rm tools pnpm test
docker compose run --rm tools pnpm typecheck
docker compose run --rm tools pnpm build
docker compose logs -f
docker compose down          # keeps volumes and tmux sessions
```

Production uses `.docker/compose/prod.yaml`. Repository layout and contributor rules live in [AGENTS.md](AGENTS.md).
