## What mtmux is

`mtmux` is a CLI you install on the machine that already runs your tmux. It
starts one Node process that serves a browser terminal and bridges it to tmux
over a WebSocket, so you can pick up a session from a phone, a tablet or another
laptop. It works with anything you would run in tmux — [coding agents](/docs/agents),
Vim, REPLs, long builds.

The shipped product is the **`mtmux`** npm package. Everything else in the
repository (`apps/web`, `apps/relay`, `apps/api`, `packages/*`) is the source
that CLI is built from, plus the split deployment shape used for containers and
the hosted service.

## Install and run

```bash
npm install -g mtmux
mtmux
```

`mtmux` on its own is the same as `mtmux start` — `start` is the default
command. It checks Node and tmux, loads or generates an auth token, serves the
terminal, and prints a pairing code plus a QR block.

- **Requirements:** Node 22+ and `tmux` on your PATH.
- **Port:** `14100` by default.
- **Bind address:** `0.0.0.0` when the machine has a real LAN address, and
  `127.0.0.1` when it does not. You do not need to pass `--host` to reach it
  from your phone.
- **Config:** `~/.mtmux/config.json`, mode `0600`.

See [Getting started](/docs/getting-started) for the walkthrough and
[CLI reference](/docs/cli) for every command and flag.

## Getting a second device on

**Scan the QR that `mtmux` printed.** That is the whole flow — one command, one
scan, and your terminal is on the phone. If the camera will not cooperate, go to
`app.mtmux.com` and type the code instead.

It works the same on your own wifi and on cellular from another country. mtmux
takes the direct path when the device can reach your machine and falls back to a
relayed tunnel when it cannot, without asking you.

The code is `slot(3) + secret(6)`. The last six digits are the password for a
PAKE and **never reach the broker**, not even as a hash; everything afterwards
is AES-256-GCM under keys neither the broker nor anyone else on the path holds.
The QR puts the code in a URL *fragment*, which browsers never send to a server.

Already at the browser instead of the terminal? `mtmux pair <code>` runs the
same handshake from the other end.

Read [How pairing works](/docs/pairing) and [The sealed tunnel](/docs/sealed-tunnel)
for the details, both of which are checkable against `packages/crypto`.

## Three ways to run it

| Shape | Command | When |
| --- | --- | --- |
| **CLI, single port** | `mtmux` | The normal case. One process serves the web UI and the relay WebSocket (same-origin at `/_relay`) on one port. |
| **CLI, LAN only** | `mtmux start` | The default. Serves this network and contacts no broker at all. |
| **Split web + relay** | `pnpm dev:split`, Docker, PM2 | Container and multi-tenant deployments where the web app and relay are separate services. See [Deployment](/docs/deployment). |

## Nothing here is mandatory

An account is optional — anonymous pairing keeps working forever, and
[Accounts](/docs/accounts) explains exactly what signing in adds. The hosted
broker is optional too: it is only reached when you ask with `--hosted`, and you can point the CLI at your own
with `MTMUX_API_URL`. See [Self-hosting](/docs/self-hosting).
