title: File Browser
description: Browse, edit, upload and preview files on the host.
---

The file browser works inside the directories allowed by `ALLOWED_PATHS`. In CLI
mode that defaults to `$HOME`; `--allowed-paths` narrows or widens it.

## Browsing

- Click a directory to enter it; use the breadcrumb or the Home button to go
  back up.
- Filter by name as you type.
- Toggle between **list** and **grid** views.
- Sort by name, modified date or size.
- Right-click — or long-press on touch — for a context menu.
- **cd in Terminal** on a directory sends `cd <path>` to the active session.

The browser opens at the relay's default allowed directory rather than a
hardcoded path.

## Creating and changing

| Action | Notes |
| --- | --- |
| New file | Inline name entry |
| New folder | Inline name entry |
| Rename | Inline |
| Delete | Behind a confirmation |
| Upload | File picker or drag-and-drop; sent base64 in 64 KiB chunks |

Uploads are capped at **10 MB**. A partial upload is deleted if it goes over the
cap or if the connection drops.

## Editing

Clicking a text file opens it in **Monaco**, loaded from the app rather than a
CDN.

- `Ctrl/Cmd+S` saves. Writes are capped at **1 MB**.
- The file is watched while open, and the watch is re-armed on every reconnect.
  An external change raises a banner with a Reload button rather than silently
  overwriting your buffer.
- Files over **100 KB** are read truncated and open read-only, as do files the
  relay reports as not writable.
- Word wrap toggles; the status bar shows size, permissions and modified time.
- Closing with unsaved changes asks first.
- **Open in new session** and **Send to current session (vim)** hand the file to
  the terminal instead.

## Previewing

Non-text files get a viewer rather than the editor:

- **Images** — with a fit / actual-size toggle over a checkerboard
- **Video** and **audio** — with native controls
- **PDF** — in an iframe
- **Anything else** — an icon, a category and a download button

There is an **Open as Text** escape hatch for files detected as binary that
are not.

## Watching

Directory watching uses chokidar at `depth: 0` — the directory you are looking
at, not its subtrees. Changes below that level do not appear until you navigate
into them.

## Media and downloads need the direct path

Embedded media are fetched with an `Authorization: Bearer` header, so the token
never appears in a URL. Explicit downloads put the token in the query, because
an `<a download>` cannot carry headers.

Both are plain HTTP `GET /file` requests. A **tunnelled** session has no HTTP
route to the relay — only sealed WebSocket frames — so previews and downloads
are unavailable there and the UI says so rather than 404ing. Everything else
(browsing, reading, editing, uploading) works identically on both paths.

## Security

Every operation passes the path guard, which resolves symlinks on both the
target and each allowed root before comparing. A symlink pointing out of an
allowed directory does not escape it, and the relay refuses to delete an allowed
root. See [Security](/docs/security#file-access).
