```bash
mtmux doctor
```

`doctor` answers "why isn't this working?" without a support thread. It runs eight
checks in dependency order, so the first failure is the real cause rather than a
symptom of an earlier one.

```
  ✓ Node          v22.14.0
  ✓ tmux          tmux 3.4
  ✓ tmux server   2 sessions
  ✓ Port 14100    free
  ✓ Config        /home/you/.mtmux/config.json
  ✓ mkfifo        available
  ! Broker        https://api.mtmux.com unreachable
    → Check your network, or drop `--hosted` and serve this network only.
  ✓ mtmux         no version service

  Ready, with 1 caveat.
```

| Flag | Default | Description |
| --- | --- | --- |
| `-p, --port <number>` | `14100` | Which port to check |
| `--api <url>` | `https://api.mtmux.com` | Which broker to probe |

## Reading the output

Three levels, and the distinction matters:

| Glyph | Meaning |
| --- | --- |
| `✓` | Fine — move on. |
| `!` | The hosted path is unavailable, but local still works. |
| `✗` | Nothing will work until this is fixed. |

Anything at `✗` sets the exit code to `1`. Warnings alone exit `0`, so `doctor`
is safe in a script that only wants to know whether mtmux can run at all.

Each non-`✓` line is followed by what to actually do about it, in the
imperative.

## The checks

### Node

Fails below **v22**. The CLI depends on WebCrypto in Node core for sealed
frames, and on Node 22 language features throughout.

Fix: install Node 22 or newer.

### tmux

Fails when `tmux -V` does not run. The hint is platform-aware —
`brew install tmux` on macOS, `sudo apt install tmux` on Linux.

### tmux server

Runs `tmux list-sessions` and reports the count. This is not the same check as
"tmux is installed": a socket owned by another user is the classic cause of "no
sessions listed" on a shared box.

- **`no server running`** is reported as **ok**, not a problem. It is the normal
  cold-start state; mtmux starts one on demand.
- Anything else is a **warning**, with the fix: run mtmux as the user that owns
  the tmux socket, or set `TMUX_SOCKET`.

### Port

Three outcomes:

- **Held by this mtmux** — reported as ok, with the pid, because that is what
  "already running" looks like.
- **Free** — ok.
- **Held by something else** — a **failure**. Pick another port with `--port`, or
  stop whatever holds it.

Pass `-p` to check whichever port you actually intend to use.

### Config

Checks the permissions on `~/.mtmux/config.json` (or `$MTMUX_CONFIG_DIR/config.json`).

- **No file yet** — ok, it is created on first run.
- **Any group or other permission bit set** — a **warning**, with the exact
  `chmod 600` command. That file holds the auth token and an Ed25519 secret key.

### Broker

Fetches `<api>/health` with a 5-second timeout and reports the round trip.

A failure here is **always a warning, never an error**. `mtmux start` without `--hosted` is
fully functional without a broker, and calling it a failure would misrepresent
an offline machine as a broken install.

### mtmux

Reads `<api>/v1/version` and compares this CLI against two numbers the broker
reports: `minCli`, the version below which that broker refuses to pair, and
`latest`, the version it would like you on.

Three rules, all of them about not crying wolf:

- **A version it cannot parse is never "too old".** Telling someone to upgrade
  a CLI that is already current is unfixable advice — the upgrade changes
  nothing and there is nowhere else to look.
- **A broker with no opinion produces no line.** Self-hosted brokers that never
  set `API_LATEST_CLI` or implement `/v1/version` say nothing, and this check
  reports that as fine.
- **It is never a failure.** Like the broker check, a warning at most.

`API_ADVISORY` is printed verbatim if the broker sets one. It is the one
channel that reaches a running CLI without a release — see
[Configuration](/docs/configuration#the-protocol-floor).

## When doctor is clean but it still does not work

Then the problem is between the browser and the machine rather than on the
machine. Work through [Troubleshooting](/docs/troubleshooting), which is
organised by symptom.
