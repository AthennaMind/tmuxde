## How to resume

Read the three plans. Check the boxes below against `git status` and the named files. Development stack must be up (`docker compose up -d --build --wait`). Run `docker compose run --rm tools pnpm test`, `pnpm typecheck`, `docker compose run --rm gotools go test ./...` before picking up the next open task. Do not commit. The user commits.

### Verification recipe

- Development URL `https://$LOCAL_DOMAIN:18443`. Sign in by opening `https://$LOCAL_DOMAIN:18443/login#token=<token>` with the token from `.docker/.env.token` (the file holds the bare 64 hex token). Open it with a fresh `playwright-cli -s=<name> open --config=/tmp/pwcfg/cli.config.json <url>`; the config uses headless Chromium and ignores the local CA. Use a distinct session name per task.
- The dev server runs its own tmux in `server-dev`. Session `test` belongs to the user. Create your own: `docker compose exec server-dev tmux -S /tmp/tmuxde-dev/tmux.sock new-session -d -s <name> -c /tmp/tmuxde-dev/scratch/<name>`. Kill it when done.
- Fixture repositories go under `/tmp/tmuxde-dev/scratch` inside the container, for example `docker compose exec server-dev sh -c 'cd /tmp/tmuxde-dev/scratch && mkdir g && cd g && git init -q -b main && git -c user.name=t -c user.email=t@example.invalid commit -q --allow-empty -m init'`. `/repo` is this checkout, read only, with real history for paging.
- Go changes rebuild the dev binary through air within seconds (`docker compose logs -f server-dev`). UI changes arrive through Vite HMR.
- Never touch the host tmux. Never run `docker compose down`.
