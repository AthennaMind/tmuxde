A coding agent is a terminal program. tmux keeps terminal programs alive across
disconnects, and mtmux serves tmux to a browser. There is no agent integration
in mtmux, no plugin, and no per-agent configuration — which is why an agent
released next month works here on the day it ships.

This section is reference material for the setup: what each part is responsible
for, what survives a dropped connection, and where the configuration for each
behaviour actually lives.

<Callout type="warn" title="mtmux sends no notifications">
  Nothing in mtmux pushes, buzzes, emails or alerts. It has no notification
  service, no daemon watching your panes, and no channel to your phone that it
  initiates. Everything on [Notifications](/docs/agents/notifications) is
  configuration you own, in your agent, your tmux, your terminal emulator or
  your own push service. mtmux is what you open **after** something else has
  paged you.
</Callout>

## What each layer is responsible for

| Layer                | Responsibility                                           | Configured in                                                                                             |
| -------------------- | -------------------------------------------------------- | --------------------------------------------------------------------------------------------------------- |
| The agent            | Doing the work; emitting its own lifecycle events        | The agent's own config — see [Claude Code](/docs/agents/claude-code), [Codex CLI](/docs/agents/codex-cli) |
| tmux                 | Keeping the process alive and detached from any terminal | `~/.tmux.conf`                                                                                            |
| mtmux                | Serving that tmux to a browser, and admitting devices    | `~/.mtmux/config.json`, flags — see the [CLI reference](/docs/cli)                                        |
| Your phone or laptop | Reading and answering                                    | Nothing; it is a browser                                                                                  |

The important consequence: **mtmux is not in the loop while the agent runs.**
Close the tab and the agent carries on, because the agent is a child of tmux and
tmux is a child of nothing. See [Architecture](/docs/architecture) for how the
pieces connect.

## The shortest complete setup

```bash
npm install -g mtmux          # once
tmux new -s agent             # a session for the agent to live in
# start your agent inside that session, then detach with Ctrl-b d
mtmux                         # serve this machine's tmux, print a code
```

Scan the QR or type the nine digits at `app.mtmux.com`. Full walkthrough in
[Getting started](/docs/getting-started); the code itself is explained in
[How pairing works](/docs/pairing).
