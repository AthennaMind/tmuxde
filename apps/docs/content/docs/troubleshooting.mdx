## Start here

```bash
mtmux doctor
```

Six checks in dependency order, so the first failure is the cause rather than a
symptom. See [`mtmux doctor`](/docs/doctor). If it is clean, the problem is
between the browser and the machine — keep reading.

## Starting up

### "tmux not found in PATH"

`mtmux` refuses to start without tmux. `brew install tmux` on macOS,
`sudo apt install tmux` on Linux.

### "Node 22+ required"

Upgrade Node. The CLI uses WebCrypto from Node core for sealed frames.

### The port is already in use

```bash
mtmux status     # is it your own mtmux?
mtmux stop       # stop it
mtmux start -p 9000
```

`mtmux doctor` distinguishes "held by this mtmux" from "held by something else"
— the first is not a problem.

### It bound loopback and I wanted the LAN

`mtmux` binds `0.0.0.0` only when it finds a usable private IPv4 address on a
non-virtual interface. If your only address is on a Docker bridge, a VM
host-only network or a VPN overlay (Tailscale, ZeroTier, WireGuard), that is
excluded on purpose — advertising it as "your network" would be misleading — and
it falls back to `127.0.0.1`.

Force it:

```bash
mtmux start --host 0.0.0.0
```

## Connecting

### The phone cannot reach the Network address

- Confirm both devices are on the same network and not on a guest SSID with
  client isolation.
- Check the host firewall allows inbound on the port.
- The address in the banner is the one to use — `localhost` is meaningless on
  another device.

### "Authentication failed"

- The token is case-sensitive and must match exactly.
- A `--local` LAN sign-in dies when the server restarts, because those tokens
  live only in relay memory. Scan the new code. Devices paired with a
  code are re-admitted automatically and are not affected.
- After 5 failed attempts from one address, further attempts are refused for 30
  seconds, doubling up to 15 minutes — _including correct ones_. Wait it out.

### The socket connects and immediately closes

- Nothing was sent within 5 seconds. The **first** message on the socket must be
  `auth`.
- Or you hit the connection cap: 100 total, 10 per address, closed with code 1013.

### It keeps reconnecting

- Behind a reverse proxy, confirm `Upgrade` and `Connection` headers are
  forwarded and `proxy_read_timeout` is generous — 3600s or more.
- `IDLE_TIMEOUT_MINUTES` closes idle connections after 30 minutes by default.
  Set it to `0` to disable.
- Check the origin: with a non-empty `CORS_ORIGINS`, an origin not on the list
  is rejected at the upgrade with a 403.

## Pairing

### "Pairing code is invalid or already used"

LAN nonces are single-use and only one is live at a time. Once a device signs
in, mtmux prints a fresh code — use that one, not a screenshot.

### The pairing code failed

A wrong guess destroys the code by design, and the page offers a new one. Get
fresh digits and try again. Codes also expire.

### `mtmux pair` says nothing is serving

`mtmux pair` needs a server already running on that port. Start one first, or
pass the right `-p`.

### The tunnel is unavailable

`mtmux start` prints a dim note under the addresses when it could not reach the
broker, and carries on serving locally. Check with `mtmux doctor` — the broker
check is a warning, never a failure, because local mode is fully functional
without it.

### Downloads and image previews do not work

Expected on a **tunnelled** session. Those are plain HTTP `GET /file` requests
and a tunnel carries only sealed WebSocket frames. Get onto the same network as
the machine, or pair without `--tunnel-only` so the direct path can win.

## Terminal

### Blank after attaching

- The session may simply have produced no output yet. Type something.
- Confirm tmux is running as the same user: `tmux list-sessions`.
- A tmux socket owned by another user is the classic cause on a shared box. Set
  `TMUX_SOCKET` or run mtmux as that user.

### Only part of each line renders

Turn off **GPU Rendering** in Settings and reload. The WebGL renderer mis-scales
cells by `devicePixelRatio` on some HiDPI screens.

### It does not resize properly

The client refits on container, window, orientation and visual-viewport changes.
If it is stuck, reload the page.

### Special keys

- macOS: Option is mapped as Meta.
- Mobile: use the keyboard toolbar. Ctrl and Alt are sticky — tap, then press a
  letter.

## Sessions and files

### "Session not found"

It exited or was killed elsewhere. Refresh the list.

### Cannot create a session

Check `tmux -V` and that `TMUX_DEFAULT_SHELL` points at a shell that exists.

### "Access denied" on a file

The path is outside `ALLOWED_PATHS`. In CLI mode, widen it:

```bash
mtmux start --allowed-paths /home/me,/var/log
```

Note that symlinks are resolved before the check, so a link out of an allowed
directory is still denied.

### A file opened read-only

It is over 100 KB — reads truncate above that — or the relay reports it as not
writable.

### An upload or a save failed

Caps are 10 MB for an upload, 1 MB for a save. Neither is configurable.

### Changes in a subdirectory do not appear

Watching runs at `depth: 0`. Navigate into the directory.

## Performance

### It feels slow

- Leave GPU rendering on unless it renders incorrectly.
- Reduce scrollback in Settings.
- Close sessions you are not using.

### High latency

- The toolbar shows round-trip latency, measured by ping/pong every 10 seconds.
- A tunnelled session goes browser → broker → your machine. Getting onto the
  same network lets the direct path win and removes that hop.

## Getting help

Include the output of `mtmux doctor` and `mtmux version` in any report:
[github.com/mtmux/mtmux/issues](https://github.com/mtmux/mtmux/issues).
