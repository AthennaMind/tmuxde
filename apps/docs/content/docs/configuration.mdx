<Callout type="info" title="Running the CLI?">
  You almost certainly want the [CLI reference](/docs/cli) instead. `mtmux`
  takes flags — `--port`, `--host`, `--local`/`--hosted`, `--token`,
  `--allowed-paths` — and sets the relay's variables for you. The tables below
  matter when you deploy the split model or run your own broker.
</Callout>

## CLI

| Variable              | Default                 | Effect                                                                           |
| --------------------- | ----------------------- | -------------------------------------------------------------------------------- |
| `MTMUX_CONFIG_DIR`    | `~/.mtmux`              | Directory holding `config.json` and `server.json`                                |
| `MTMUX_API_URL`       | `https://api.mtmux.com` | Pairing broker base URL. `--api` overrides it; `mtmux config set api` stores it. |
| `MTMUX_APP_URL`       | `https://app.mtmux.com` | Web client origin used to build the pairing link and the QR                      |
| `MTMUX_BUILD_API_URL` | —                       | **Build time only.** Bakes a broker origin into the bundled web client.          |

`MTMUX_BUILD_API_URL` is read when the CLI is built, not when it is run. Next
inlines `NEXT_PUBLIC_*` at build time, so a CLI that should talk to your broker
by default has to be built with it set. At runtime, `MTMUX_API_URL` is the knob.

`~/.mtmux/config.json` is written with mode `0600`, because it holds the auth
token and an Ed25519 secret key. [`mtmux doctor`](/docs/doctor) warns if it is
not.

## Relay server

Read once at import, validated with Zod, and a bad value stops the process
rather than being quietly ignored. In CLI mode `mtmux start` sets these itself.

| Variable               | Default                   | Description                                                         |
| ---------------------- | ------------------------- | ------------------------------------------------------------------- |
| `RELAY_PORT`           | `14300`                   | WebSocket server port                                               |
| `RELAY_HOST`           | `127.0.0.1`               | Bind address                                                        |
| `AUTH_TOKEN`           | `change-me-in-production` | Token clients must present as their first message                   |
| `ALLOWED_PATHS`        | `/home`                   | Comma-separated directories the file browser may touch              |
| `TMUX_SOCKET`          | —                         | Explicit tmux socket path                                           |
| `TMUX_DEFAULT_SHELL`   | `/bin/bash`               | Shell for newly created sessions                                    |
| `WS_RATE_LIMIT`        | `100`                     | Inbound messages per second, per connection                         |
| `IDLE_TIMEOUT_MINUTES` | `30`                      | Idle disconnect. `0` disables the reaper.                           |
| `CORS_ORIGINS`         | `http://localhost:14100`  | Comma-separated allowed origins. Empty means no origin restriction. |

### Two startup guards

The relay **refuses to boot** when:

- `AUTH_TOKEN` is empty or still `change-me-in-production` **and** `RELAY_HOST`
  is not loopback. A network-exposed relay with the well-known token is
  effectively open. On loopback it is allowed, which keeps `pnpm dev` friction
  free.
- `NODE_ENV=production` and any entry in `CORS_ORIGINS` starts with
  `http://localhost`.

Generate a token with `openssl rand -hex 32`.

### On `CORS_ORIGINS` being empty

An empty list means "no origin restriction", not "reject everyone". CLI
single-port mode sets it empty on purpose: everything is same-origin there, so
there are no cross-origin requests to police.

### On `ALLOWED_PATHS`

Enforcement resolves symlinks on both the target and each allowed root before
comparing, so a symlink out of an allowed directory does not escape it. Every
read, write, create, delete, rename, upload and watch goes through the same
guard, and the relay refuses to delete an allowed root itself.

Size caps are fixed, not configurable: 100 KB for a truncating read, 1 MB for a
write, 10 MB for an upload.

## Web app

| Variable                | Default | Description                                                                                                        |
| ----------------------- | ------- | ------------------------------------------------------------------------------------------------------------------ |
| `NEXT_PUBLIC_RELAY_URL` | —       | Relay WebSocket URL. **Split model only** — leave unset in CLI mode, where the socket is same-origin at `/_relay`. |
| `NEXT_PUBLIC_API_URL`   | —       | Pairing broker origin the browser should use.                                                                      |

Both are inlined at build time. Setting them on a running process changes
nothing about the bundle already being served — which is why
`scripts/deploy-hosted.mjs` greps the built chunks for the API origin before it
will deploy.

In production use `wss://`:

```bash
NEXT_PUBLIC_RELAY_URL=wss://terminal.example.com/ws
```

## Pairing broker

`apps/api`. Same fail-fast shape as the relay: a misconfigured broker refuses to
boot rather than running with a quietly wrong abuse limit.

| Variable                       | Default                  | Description                                                                                                                           |
| ------------------------------ | ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------- |
| `API_PORT`                     | `14400`                  | HTTP + WebSocket port                                                                                                                 |
| `API_HOST`                     | `127.0.0.1`              | Bind address                                                                                                                          |
| `API_CORS_ORIGINS`             | `http://localhost:14100` | Comma-separated allowed browser origins                                                                                               |
| `API_CLAIMS_PER_MINUTE`        | `5`                      | Claim POSTs per minute, per address. Bounds allocation only — the guess itself is charged below.                                      |
| `API_SLOT_CLAIMS_PER_MINUTE`   | `4`                      | Claims **attached** per minute for one slot, ignoring the caller's address                                                            |
| `API_GLOBAL_CLAIMS_PER_MINUTE` | `200`                    | Claims attached per minute service-wide. Derived from the slot space: an attacker must never sweep it faster than codes are reissued. |
| `API_MAILBOXES_PER_MINUTE`     | `10`                     | New mailboxes per minute, per address                                                                                                 |
| `API_MIN_PROTOCOL`             | package default          | Lowest pairing protocol version accepted. `0` accepts every client, including one that declares no version.                           |
| `API_ADVISORY`                 | _(empty)_                | A line reported by `GET /v1/version` and shown by `mtmux doctor`. Say something urgent to every running CLI without shipping code.    |
| `API_TUNNEL_MAX_BYTES`         | `1073741824` (1 GiB)     | Bytes forwarded per tunnel, both directions                                                                                           |
| `API_TUNNEL_MAX_MINUTES`       | `720` (12 h)             | Tunnel lifetime                                                                                                                       |
| `API_TUNNEL_MAX_STREAMS`       | `16`                     | Concurrent streams per tunnel. A denial-of-service bound: a `stream:open` past it is refused, and the tunnel stays up.                |

The broker **refuses to boot** when `NODE_ENV=production` and `API_CORS_ORIGINS`
still contains a `localhost` origin.

### The protocol floor

`GET /v1/version` reports `{ protocol, floor, advisory? }`. A client below
`floor` gets `426 Upgrade Required` from the pairing routes and a raw
`HTTP/1.1 426` from the WebSocket upgrade, before any frame is exchanged.

The floor is **your** decision, not ours. `API_MIN_PROTOCOL=0` turns it off
entirely, which is the right setting for a broker whose clients you control and
whose upgrade schedule is nobody else's business.

The rate limits are part of the security argument, not capacity management —
see [How pairing works](/docs/pairing#why-the-secret-is-enough).

### Reverse DNS and per-device certificates

An unfinished feature, off unless configured. Pairing and the tunnel work fine
without it; only the direct path would benefit.

| Variable               | Default                  | Description                                       |
| ---------------------- | ------------------------ | ------------------------------------------------- |
| `CLOUDFLARE_API_TOKEN` | —                        | Token for DNS record management                   |
| `CLOUDFLARE_ZONE_ID`   | —                        | Zone to write records into                        |
| `DNS_ZONE`             | —                        | The zone name                                     |
| `ACME_ENABLED`         | `false`                  | Additional explicit gate for certificate issuance |
| `ACME_DIRECTORY`       | Let's Encrypt production | ACME directory URL                                |
| `ACME_EMAIL`           | —                        | Contact address for the ACME account              |

Reverse DNS turns on only when all three of `CLOUDFLARE_API_TOKEN`,
`CLOUDFLARE_ZONE_ID` and `DNS_ZONE` are set. Certificate issuance additionally
requires `ACME_ENABLED=true` and `ACME_EMAIL`, because Let's Encrypt allows 50
certificates per registered domain per week and every install wanting its own
would blow through that immediately.

## Hosted accounts (optional)

The accounts layer sits on top of the broker and almost nobody self-hosting will
configure it. **Leaving `DATABASE_URL` unset is a supported configuration**, not
an error: the account and billing endpoints answer `503` with
`{"error": "Accounts are not enabled on this broker.", "plan": "free"}`, and
pairing and tunnelling are entirely unaffected. Every value here has a working
default for that reason.

Migrations run at boot rather than as a deploy step, because the broker is one
process that owns its own file. A database that fails to open is logged and
swallowed — booting without accounts is a working broker, and refusing to boot
would take pairing down over a feature the operator may not use.

| Variable                       | Default                            | Description                                                          |
| ------------------------------ | ---------------------------------- | -------------------------------------------------------------------- |
| `DATABASE_URL`                 | —                                  | SQLite file for accounts. Empty disables accounts entirely.          |
| `BETTER_AUTH_URL`              | derived from `API_HOST`/`API_PORT` | Public origin of the API, and the issuer sessions are signed against |
| `BETTER_AUTH_SECRET`           | a development sentinel             | Session signing secret                                               |
| `APP_ORIGIN`                   | `http://localhost:14100`           | Public origin of the browser app                                     |
| `AUTH_COOKIE_DOMAIN`           | —                                  | e.g. `.mtmux.com`, so `app.` and `api.` share a session              |
| `AUTH_TRUSTED_ORIGINS`         | `APP_ORIGIN` + `API_CORS_ORIGINS`  | CSRF allow-list, separate from CORS                                  |
| `SERVER_ONLINE_WINDOW_SECONDS` | `90`                               | How recently a server must have beaten to count as online            |
| `ACCOUNT_REQUESTS_PER_MINUTE`  | `120`                              | Per-user sliding window                                              |
| `ACCOUNT_WRITES_PER_MINUTE`    | `30`                               | Per-user sliding window for writes                                   |
| `DODO_PAYMENTS_API_KEY`        | —                                  | Billing provider key                                                 |
| `DODO_ENVIRONMENT`             | `test_mode`                        | `test_mode` or `live_mode`                                           |
| `DODO_WEBHOOK_KEY`             | —                                  | Webhook signature key                                                |
| `DODO_PRODUCT_PRO_MONTHLY`     | —                                  | Product id                                                           |
| `DODO_PRODUCT_PRO_YEARLY`      | —                                  | Product id                                                           |

Two guards fire when `NODE_ENV=production` **and** `DATABASE_URL` is set:

- `BETTER_AUTH_SECRET` must not be the development sentinel. Sessions signed
  with a well-known secret are forgeable by anyone who has read the source.
- `BETTER_AUTH_URL` must be `https://`. Session cookies are issued `Secure` and
  would never be sent back over plain HTTP.

`DODO_ENVIRONMENT` defaults to `test_mode` although the provider's SDK defaults
to live: a missing variable should bill nobody.

`AUTH_COOKIE_DOMAIN` must stay empty for local development. A cookie scoped to
`.mtmux.com` is simply never sent to `127.0.0.1`, and the symptom — a 401 on a
request that just succeeded at signing in — points nowhere near the cause.

## Cross-cutting

| Variable        | Description                                            |
| --------------- | ------------------------------------------------------ |
| `NODE_ENV`      | `production` turns on the CORS and secret guards above |
| `NEXT_DIST_DIR` | Overrides Next's build output directory                |

These, and every variable above that affects a build, are declared in
`turbo.json`'s `globalEnv` so Turborepo invalidates its cache when they change.
