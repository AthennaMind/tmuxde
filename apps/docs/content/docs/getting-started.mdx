## Prerequisites

- **Node.js 22 or newer.** `mtmux` exits immediately on anything older.
- **tmux** on your PATH — `brew install tmux`, `sudo apt install tmux`, or your
  distribution's equivalent.

You do not need Docker, a reverse proxy, a certificate, or a port forward.

## The short version

<Steps>
<Step title="Install the CLI on the machine that runs tmux">

</Step>

<Step title="Run it">

It serves the terminal on port `14100`, opens a sealed tunnel, and prints a QR

The rest of this page is each of those in detail, plus what to do when one of
them does not go to plan.

## Install

```bash
npm install -g mtmux
```

Any global installer works:

```bash
pnpm add -g mtmux
bun install -g mtmux
```

## Run

```bash
mtmux
```

`start` is the default command, so bare `mtmux` and `mtmux start` do the same
thing. On start the CLI:

1. Checks Node 22+ and that `tmux -V` succeeds. Either failing is fatal.
2. Loads `~/.mtmux/config.json`, or generates a fresh 32-byte random token and
   writes the file with mode `0600`.
3. Picks a bind address — `0.0.0.0` if this machine has a usable LAN address,
   `127.0.0.1` if it does not.
4. Serves the web client and the relay WebSocket on one port (`14100`), with the
   socket same-origin at `/_relay`.
5. Opens a sealed tunnel and arms a pairing code, unless you passed
   `--local`.
6. Re-admits every device that paired with this machine before.
7. Prints the banner and opens a browser on this machine.

Press **Ctrl+C** to stop.

## Getting your phone on

**Scan the QR.** That is the whole thing. It opens the join page with the code
already in it, and the terminal loads — no taps, no typing, no second command.

If the camera will not cooperate, go to **app.mtmux.com** on the device and type
the code into the field it shows. It is grouped for reading aloud,
so `492716384` prints as `492 716 384`.

This works from your own wifi *and* from cellular in another country. mtmux
takes the direct path when the device can reach your machine and falls back to a
relayed tunnel when it cannot — you do not choose, and the switchover is
invisible.

The QR encodes `https://app.mtmux.com/j#492716384`. Everything after the `#` is a
URL **fragment**, which browsers never send to a server, so the half of the code
that matters never reaches anyone's access log. The page strips it from the
address bar before it does anything else.

`--no-qr` drops the QR block and keeps the digits, which is what you want in a
terminal that mangles block characters. When there is neither a code nor a QR —
`--local --no-qr` — the banner falls back to printing the auth token, because
that is the only case left where someone has to authenticate by hand.

### If the browser is already open

`mtmux pair` runs the same handshake from the other end: open
`https://app.mtmux.com/pair` on the device, read the code it shows, and
quote them back on the machine.

```bash
mtmux pair 492716384
```

Handy when you are already at the browser, or pairing a machine you reached over
SSH. See [How pairing works](/docs/pairing).

### Paired devices stay paired

Restarting mtmux does not un-pair anything — the tokens it derived with each
browser are stored in `~/.mtmux/config.json` and replayed on boot. A device is
trusted until it goes 90 days unseen or you run `mtmux devices revoke <id>`.
Reloading the browser does not force a re-pair either.

## Common flags

```bash
mtmux start --local                  # LAN and loopback only; contacts no broker
mtmux start -p 9000                  # different port
mtmux start -n "build box"           # name this machine in the dashboard
mtmux start --no-open                # don't open a browser here
mtmux start --no-qr                  # code without the QR block
mtmux start --json                   # machine-readable startup record
```

`mtmux local` is an alias for `mtmux start --local`. The full list is in the
[CLI reference](/docs/cli).

## Managing the token

The token is generated once and reused. Rotating it deliberately does **not**
un-pair your devices — device keys and peer records survive.

```bash
mtmux token print          # show the current token
mtmux token rotate         # generate a new one
mtmux token set <value>    # set a specific value
```

If you used the CLI back when it was published as `tmuxremote`, the token at
`~/.tmuxremote/config.json` is adopted on first run rather than replaced, so
bookmarked login URLs keep working.

## Checking on it

```bash
mtmux status     # what's running here, and how it's reachable
mtmux stop       # stop it
mtmux doctor     # check Node, tmux, the port, config perms, the broker
mtmux version    # versions of mtmux, node, tmux, and the platform
```

[`mtmux doctor`](/docs/doctor) is the first thing to run when something is not
working.

## Working on mtmux itself

To develop the monorepo rather than use the CLI:

```bash
git clone https://github.com/mtmux/mtmux.git
cd mtmux
pnpm setup     # pnpm install + .env from the template
pnpm dev       # web + relay on ONE port (14100), same shape as `mtmux start`
```

`pnpm dev` runs the shipped single-port topology so single-port bugs surface
while you work. Escape hatches:

```bash
pnpm dev:split     # split model: web 14100 + relay 14300 (Docker/PM2 shape)
pnpm dev:pairing   # the hosted-pairing topology, broker included
pnpm dev:docs      # this docs site on 14102
```

See [CONTRIBUTING.md](https://github.com/mtmux/mtmux/blob/main/CONTRIBUTING.md).
