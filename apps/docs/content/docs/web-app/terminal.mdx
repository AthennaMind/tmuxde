## Rendering

The terminal is [xterm.js](https://xtermjs.org/) with these addons:

| Addon                                         | Always on?                         |
| --------------------------------------------- | ---------------------------------- |
| **Fit** — sizes the terminal to its container | yes                                |
| **Search** — finds text in scrollback         | yes                                |
| **Unicode 11** — emoji and wide characters    | yes                                |
| **Web Links** — clickable URLs in output      | yes                                |
| **WebGL** — GPU-accelerated rendering         | only when GPU rendering is enabled |

GPU rendering is **on by default** and can be turned off in Settings. The
setting is read once when the terminal initialises, so toggling it applies after
a reload — the Settings panel says so. If the WebGL context is lost the addon is
disposed and rendering continues without it. Turn it off if only part of each
line is visible, which is a known cell-scaling problem on some HiDPI screens.

Option is mapped as Meta on macOS.

## Resizing

Resize is driven by a `ResizeObserver`, window resize, `orientationchange`,
`visualViewport` resize and scroll, and an `IntersectionObserver`, all funnelled
through one debounced fit. Duplicate `terminal:resize` messages are suppressed.

That machinery exists because a mobile browser changes the visual viewport
without changing the layout viewport when the keyboard appears, and a terminal
that does not notice ends up drawing under it.

## Search

Open it from the toolbar on desktop, or the search button in the mobile keyboard
toolbar.

| Key           | Action         |
| ------------- | -------------- |
| `Enter`       | Next match     |
| `Shift+Enter` | Previous match |
| `Escape`      | Close          |

## Keyboard shortcuts

These are bound by the app. Everything else goes through to the PTY.

| Shortcut              | Action                       |
| --------------------- | ---------------------------- |
| `Ctrl/Cmd` `+` or `=` | Increase font size           |
| `Ctrl/Cmd` `-`        | Decrease font size           |
| `Ctrl/Cmd` `0`        | Reset font size              |
| `Ctrl/Cmd` `B`        | Toggle the sidebar           |
| `Ctrl/Cmd` `E`        | Switch to the Files tab      |
| `Ctrl/Cmd` `K`        | Command palette              |
| `?`                   | Keyboard shortcuts dialog    |
| `Ctrl/Cmd` `S`        | Save, inside the file editor |

`Ctrl+C`, `Ctrl+D`, `Ctrl+L` and `Ctrl+Z` are _not_ app shortcuts — they pass
straight through to the shell, which is why they behave exactly as they do in a
local terminal.

## Copy and paste

Copy takes the current selection and writes it to the clipboard. Paste reads the
clipboard and sends it as terminal input. Both use the browser Clipboard API and
therefore need a secure context or localhost.

## Command palette

`Ctrl/Cmd+K`, or the palette button in the mobile keyboard toolbar. It offers:

- **Quick actions** — Interrupt, EOF, Clear, Suspend
- **Recent commands** — the last ten from history
- **Free text** — anything typed is sent as a command and appended to history

## Settings

Persisted to `localStorage` and applied per browser:

| Setting          | Range                                                      | Default                                                |
| ---------------- | ---------------------------------------------------------- | ------------------------------------------------------ |
| Font size        | 8–24, further clamped so at least ~20 columns stay visible | 14 (13 on 769–1024px)                                  |
| Font family      | —                                                          | JetBrains Mono → Fira Code → Cascadia Code → monospace |
| Terminal theme   | the set in `@repo/ui`                                      | Dracula                                                |
| Cursor style     | block, underline, bar                                      | block                                                  |
| Cursor blink     | on/off                                                     | on                                                     |
| Scrollback lines | 100 – 50,000                                               | 5,000                                                  |
| GPU rendering    | on/off (applies after reload)                              | on                                                     |

There is no font-family picker in the UI; the stack above is what you get.

## Recordings

The toolbar's record button starts and stops a recording of the attached
session; `/r` lists the ones on the machine and plays them back in a real xterm,
so a `.cast` renders exactly as the session did. Space plays and pauses, the
arrow keys jump five seconds, and the speed control cycles 0.5× to 4×.

The button is absent — not disabled — against a machine whose mtmux predates
recording, and for a read-only share. What a recording contains, and what
sharing one gives away, is on [its own page](/docs/recording).

Seeking backwards is the one slow operation: a terminal's state is a fold over
every byte before it, so jumping back replays from the start to that point.
